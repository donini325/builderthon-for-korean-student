# 브리프: 등록하려는 학생의 눈으로 본 등록 흐름 (2026-11-02)

대상 레포: `website` (HEAD e684b06). 정본은 `docs/brand.md`(먼저 읽습니다). 근거는 사용자 2026-11-02: 사이트 사용자가 되어 등록을 하려 할 때 말이 안 되는 기능이나 UI/UX를 찾고 고칠 제안을 쓸 것. 2026-10-12의 `docs/signup-review-2026-10-12.md`(S1~S15) 뒤에 적용되거나 되돌린 것은 다시 열지 않고, 그 뒤에 새로 보이는 것만 적습니다.

## 0. 어떻게 봤나

- 배포본(`/`, `/crossing`, `/en/crossing`)을 1440과 390에서 Playwright로 걸었습니다. 지금 등록 창은 열리기 전(`CROSSING_WINDOW.opensAt` null)이라 폼은 미리 보기입니다.
- 열린 뒤의 흐름은 같은 코드를 `opensAt`만 채워 로컬 빌드로 걸었습니다(API는 201, 429로 가짜 응답). 검증, 완료 화면, 오류 화면, 다시 열기까지.
- 배경(three.js)이 헤드리스에서 1fps 정도라 모달 닫힘 애니메이션이 3초 걸렸습니다. 뒷면 클릭 닫힘은 정상이고, 측정 잡음이라 적지 않습니다.

정상 확인: 열면 포커스가 닫기 버튼, Tab 순환, Esc 닫힘, 뒷면 클릭 닫힘, 입력 18px(iOS 확대 없음), 빈 제출 때 오류 8개가 칸마다 붙고 첫 오류 칸으로 포커스, 잘못된 이메일 문구, 20초 타임아웃, 초안 복원, `/?register=1` → `/crossing`으로 넘어가 모달 열림, EN 모달과 완료 화면 정상, 헤더 "등록" 칩 착지(헤더 아래 12px), 폰 모달 88dvh 안쪽 스크롤 1,812px(2.7화면).
